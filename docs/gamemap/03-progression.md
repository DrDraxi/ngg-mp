## 9. Challenges

- `ChallengeSystem` (singleton): `ChallengeSet m_mainChallengeSet`, `ChallengeSet m_challengeSet` (current), `string m_currentTee`, `bool m_challengeCompletedOnThisShot`, `List<string> m_preBrokenShots`, `bool m_isReplayingBounty`, `List<Ball> m_ballsInPlay`, `BountyLargeFeedback m_bountyFeedback`, `GameObject m_boundary`.

- Tees: `StandHere` (OnTriggerEnter "First Person Character" -> `Activate()` sets m_currentTee, may set m_run.m_canGolf, may LoadNewChallengeSet(m_loadChallengeSetOnEnter)). `GreatConnector.ActivateTee/DisableAllTees/GetTee/HasTee`.

## 12. Locks / doors
- `ObjectStates` (= `ProgressManager.instance.m_objectStates`), by string id:
  - `SetGates(string id, bool open)` (PicketGates[] m_gates; ids "hole1", "hole2", "securityGate").
  - `OpenDoor(string id)` (Doors[] m_doors; "hole5Shed", "bathroom", "bar", "bunkerFinal", + FPSInteractable.m_gateToOpen ids).
  - `OpenOrCloseSlidingDoor(bool open, string id)` (RFID; "topBunker", "MarketingDoor", ...), `CheckRFIDDoors()`, `CheckRFIDDoorAlreadyOpen(id)`.
  - Each calls SaveRun. Persistence is the SaveableObject active/rotation snapshot, not a door list.
- Openers: Padlock -> `DialogueManager.PlayNoTextDialogue(..., gateToOpen, ...)` -> private `PadlockSequence(gate)` (waits FPS video frame) -> SetGates/OpenDoor + PADLOCK. RFID via FPSInteractable. `ServerSequence()` (m_serverCut, `ObjectStates.ServerCut()`), `BunkerSequence()` (m_bunkerOpen), `FinalDoorSequence()` (m_bountiesRestored). Elevator `GreatConnector.instance.m_elevator` OpenTopDoors/OpenBottomDoors/RideElevator(bool down) (teleports player; toggles m_bunker GO). `Teleporter.Teleport()` -> `TeleportManager.TeleTransition(...)`.
- Code door: `Authenticator` RANDOM 4-digit code per client in Start; `InputBoard.AddInput(string)` completes challenge on match (BO_Code). Share host code.

## 17. Nondeterminism / desync
1. UnityEngine.Random: wind, spin chaos/bunker wiggle, ClubSwing.GetNewReturnRate/ResetArms, tree-hit force, Clod torque, Breakable shards, Authenticator code, TriviaBoard.ShuffleButtons, TicketShelf.Start, TargetAnimator delays (DOTween), UnlockNewBall, random dialogue line, ServerBlinks, audio.
2. Physics not reproducible (multithreaded PhysX, deltaTime coroutines, global bounceThreshold, global TerrainCollider.material). Shooter-authoritative ball, stream pose + rest position; ghosts remotely.
3. Ball.FixedUpdate reads local swing panel/club.
4. HitSequence waits on video; Breakable respawn 120 s.
5. Progression per-client in run2.txt; host must own m_run and broadcast changes.
6. Single-instance assumptions: HitManager.instance.m_ball, ChallengeSystem, MoveAndHitController, triggers keyed on names "First Person Character"/"Ball".
